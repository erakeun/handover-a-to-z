인수인계 A to Z — PC 사용 흐름 검토
2026-10-20

목적과 관찰 범위
개발 지식이 없는 사람이 시작·작성·읽기를 진행할 때 필요한 판단과 입력을 줄였다.
실제 참여자를 모집한 사용성 시험은 아니다. 기존 공개 PC 화면을 직접 따라간
인지적 워크스루와 변경 코드의 DOM 검증을 구분한다.

먼저 확인한 세 가지 문제와 변경
1. 시작 전에 긴 소개와 네 가지 동등한 선택지가 나왔다.
   ‘JSON 불러오기’는 사용자가 파일 형식을 먼저 이해하도록 요구했다.
   → 홈의 주행동을 ‘인수인계서 만들기’, ‘받은 인수인계서 보기’ 두 개로 줄였다.
     기존 문서와 예시는 보조 행동으로 남겼다. 파일 선택은 ‘받은 파일 열기’로
     표현하고, 해당 파일이 이 앱에서 전달받은 .json이라는 설명을 붙였다.
2. 업무를 선택하면 편집기가 큰 업무 목록과 빈 달력 아래로 밀렸다.
   ‘기본 3가지’라는 설명과 달리 분류·이름·시점·상황·준비 시작·방법,
   여섯 입력 컨트롤이 먼저 보였다. 실제로 여섯 항목이 필수인 것은 아니었다.
   → PC에서 큰 업무 목록과 선택한 업무를 나란히 두고 이름과 방법을 먼저 보인다.
     일정·분류·상세는 펼쳐서 적는다. 빈 문서도 두 입력으로 바로 시작한다.
     자동 저장 상태 옆에 ‘받는 사람 화면 확인’을 두어 다음 행동을 보인다.
3. 가져오기 검토에서 모든 초안의 제목·본문·분할·병합 도구가 길게 펼쳐졌다.
   일부만 가져오려면 선택을 하나씩 해제해야 했다.
   → 제목·요약을 먼저 보이고 필요한 초안만 펼친다. 검색과 보이는 항목의 묶음
     선택·해제를 제공한다. 숨겨진 선택 수와 원문 보존 안내를 계속 보여 준다.
     검색 밖의 다음 초안과 실수로 합치지 못하도록 했다.

세 흐름의 관찰 및 행동 수
행동 수는 버튼 클릭 또는 한 입력 칸 채우기를 각각 1회로 계산한다.
읽기 시간·스크롤·키 입력 글자 수·오입력 복구 시간은 포함하지 않는다.
기존은 공개 PC에서 관찰했고, 변경 후 수치는 합성 데이터의 DOM 실행 결과다.
실제 사람의 시간 절약이나 성공률로 해석할 수 없다.

A. 새 문서에서 큰 업무 3개와 세부 업무 1개
기존: 시작 1 + 영역 만들기(열기·이름·확인) 3회씩 + 업무 추가 1
      + 업무명·방법 입력 2 = 13행동.
변경: 같은 분류 결과를 만드는 경로도 13행동이다.
초기 편집 입력은 6개에서 2개로 줄이고 목록을 보며 편집하도록 바꿨다.
별도로, 분류하지 않은 첫 업무만 적는 경로는 시작·이름·방법의 3행동이다.
결과의 분류 상태가 다르므로 ‘13→3으로 단축’이라고 비교하지 않는다.

B. 기존 자료 일부를 업무로 가져오기
공개 화면에서 합성 메모 3단락의 붙여넣기→초안 검토→추가를 확인했다.
기존에는 3개 초안 모두 본문 편집기가 펼쳐졌다.
변경 후 합성 72개 초안에서 검색·묶음 선택·요약 펼치기·분할·병합·추가와
선택하지 않은 원문의 보존을 DOM으로 검증했다.
예를 들어 72개 중 검색으로 찾은 1개만 가져올 때 기존 선택 해제는 71회,
변경 후 선택 정리는 전체 해제 1 + 검색 1 + 보이는 항목 선택 1 = 3행동이다.
이 비교는 선택 정리만 해당하며 원문 검토·업무 분류·가져오기 전체 비용이 아니다.

C. 인수자가 전체 업무·이번 주·예외를 찾기
공개 가상 예시 10업무·3진행 건에서 전체 요약, 이번 주 전환,
‘권한’ 상황 검색, 업무 설명의 예외 항목을 확인했다.
전체 지도에서 한 업무를 열면 1클릭으로 상세와 예외를 볼 수 있었다.
이번 주 전환은 1클릭, 검색 후 설명 열기는 입력 1 + 펼치기 1이다.
변경 후에도 이 흐름은 유지한다. 처음 보이는 범위 탭은 7개에서 3개로 줄였다.
월별·상황별·첫날 안내·확인 필요·역할 필터는 ‘다른 기준으로 보기’에서 접근한다.
활성 필터는 숨기지 않으며 검색이 기간 탭과 별도로 적용된다는 설명을 보인다.
추가 기준은 펼치기 1행동이 더 필요하므로 모든 경로가 짧아졌다고 주장하지 않는다.

오류 복구·기존 기능
- 자동 저장 실패 및 다른 창의 변경 감지 시 덮어쓰기 중단과 파일 저장 안내 유지.
- 한국어 조합 중 첫 입력에서 입력 DOM을 교체하지 않음. 빈 문서는 가짜 업무를
  미리 저장하지 않고 실제 입력이 생길 때 기존 데이터 형식의 업무 1개를 저장.
- 수행 체크는 인계 원본과 분리. 숨긴 일정·자료·역할·근거 등 값은 삭제하지 않음.
- 전달용 전체 파일과 전체 DOCX는 부분 선택에 영향받지 않음.
  선택 DOCX·인쇄·AI의 선택 상태는 화면 이동 후 유지.
- 비밀번호·인증키 금지, 비암호화, 출처 원문 포함, AI 수동 전달 경고 유지.
- DOCX의 빈 선택 항목 설명은 함께 모으고 작성된 본문·표·줄바꿈은 보존.

실행한 검증과 하지 못한 검증
- 공개 HTTPS PC UI: 시작·3영역 생성·업무 작성·메모 3개 추가·저장 상태·
  새로고침 복원·가상 예시의 전체/주간/검색/예외 접근을 직접 관찰.
- 공개 앱의 파일 선택: 합성 PPTX를 선택하려 했으나 Chrome 확장의 로컬 파일
  접근 권한이 없어 setFiles 단계에서 실패. 파일 내용은 앱에 들어가지 않았다.
  권한 변경·file URL 열기·localhost 우회·동일 경로 재시도는 하지 않았다.
- 변경 코드: 전체 테스트 137개, 문법·정적 검사, 빌드, diff 공백 검사 통과.
  첫 입력 저장·한글 조합 이벤트·선택 상태·전체 출력 범위·원문 보존 등을 포함.
- 변경된 화면의 실제 PC 배치·실제 키보드 IME·보조기술·파일 선택·인쇄와
  다운로드 실사용은 미검증이다. 변경 후 스크린샷을 실제 검증처럼 제시하지 않는다.
- 모바일 검증과 실제 참여자 평가는 이번 범위에 포함하지 않았다.

출시 상태
이 기록의 변경은 검토용 소스와 빌드이다. main의 소스 병합과 실제 gh-pages
게시를 구분한다. 운영 게시, 접근 권한 변경, 실제 자료 공개는 이 검토에 포함하지 않는다.
