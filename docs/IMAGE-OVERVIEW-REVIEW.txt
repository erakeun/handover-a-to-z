인수인계 A to Z 0.2.0 — 사진·업무표·사용설명서 검토 기록

완성한 흐름
- 하는 방법/진행 단계 옆 사진 넣기, 파일 선택·드롭·이미지 붙여넣기 이벤트, 미리보기와 설명, 확대, 삭제 확인.
- 사진 바이트까지 단일 JSON에 포함. 기존 v1 내용 유지, 사진 추가 시 v2. 사진은 외부 서버나 AI로 보내지 않음.
- 새 임시저장은 IndexedDB. 이전 localStorage 원본을 남겨 이관하며, 완료된 트랜잭션만 저장 성공으로 표시.
- 담당 역할 > 큰 업무 > 작은 업무 제목의 자동 업무표. 제목에서 작성/열람 위치로 이동하고 복귀. 별도 표 입력 없음.
- 같은 사진과 캡션을 DOCX에 포함. DOCX·인쇄 말미에 선택 범위의 업무표 출력.
- 캡처가 빠진 사용설명서 초안: 사용방법 진입점, 인계자/인수자 3분 시작과 상세 단계 25개, 저장/전달/복구/선택 AI 안내.
- 기존 문서 가져오기는 본문 초안 추출. PDF 쪽번호만 읽힌 페이지 경고와 반복 머리말을 고려한 제목 후보 보완.

용량과 호환성
입력 사진: JPEG/PNG/정지 WebP, 8 MiB·1,600만 픽셀·한 변 8,192픽셀까지.
저장 사진: PNG/JPEG, 한 장 2 MiB, 업무당 20장, 문서당 100장·합계 16 MiB.
전달 JSON: v1 5 MiB, v2 24 MiB. 예전 v1 앱에서는 사진 포함 v2 파일을 읽을 수 없음.
기기 저장: 문서 최대 30개, 현재 목록 UTF-8 합계 64 MiB. 브라우저 실제 여유 용량은 별개.
전체 크기 PNG가 한도를 넘으면 축소 JPEG를 제시하며 사용자가 확인 후 선택. 원본 파일은 변경하지 않음.

실행한 검사
npm test: 229개 통과 / 실패 0 / 생략 0.
npm run check: 소스·테스트 문법 검사와 앱 동적 HTML/eval 미사용 검사 통과.
npm run build: 0.2.0 브라우저 번들 생성 성공.
git diff --check: 통과. 새 의존 패키지 없음.
JSON: 한글·긴 본문·사진 바이트·캡션 왕복, 새 사본 ID, 손상/과대/악성 입력 방어.
DOM: 사진 생성·확인·취소·삭제, 이벤트 기반 붙여넣기/드롭, 재시작, JSON 사본, 수행 기록 분리, 검색, 확대 복귀, 업무표 이동/복귀, 사용설명서 전환.
저장: 트랜잭션 모형에서 이관 원본 보존, 다시 열기, 충돌, quota/abort/timeout/versionchange, 저장 실패 복구, 64 MiB 사전 제한.
DOCX: 실제 OOXML 재열기·이미지 바이트 확인, LibreOffice PDF 렌더, 가로/세로 사진 3장과 캡션의 페이지 내 배치 확인.
긴 제목: 업무 30개를 포함한 DOCX/PDF, 말미 개요 10쪽에 전체 제목 보존 및 반복 표 머리글 확인.
실제 제공 문서 2개는 비공개 폴더에서만 추출/대표 페이지 렌더 검증. 원본이나 내부 정보를 공개 파일에 포함하지 않음.

검증하지 못한 것
이번 새 화면은 실제 브라우저에서 실행하지 못함. OS 파일 선택/클립보드/다운로드, 브라우저 인쇄창, 실제 새로고침·탭 종료·강제 종료 뒤 저장 복원, 화면 배치·키보드·스크린리더의 실제 동작은 미검증.
사진 코덱/canvas 및 IndexedDB 테스트는 명시적인 API/트랜잭션 모형을 사용. 통과했다고 실제 브라우저의 디스크 보존을 보장하지 않음.
사용설명서는 글 안내 초안이며 완성본으로 보고하지 않음. 실제 신규 화면 캡처는 미완료. 가짜 화면이나 실제 내부 문서 이미지를 대신 넣지 않음.
브라우저 도구의 읽기 전용 목록을 다시 확인했으며 Chrome extension(사용자 프로필) 1개만 노출됨. 별도의 격리된 테스트 브라우저는 확인되지 않음. 새 코드 0.2.0은 로컬에 있고 공개 사이트에는 0.1.1만 있어 공개 사이트 캡처로 새 기능을 검증할 수 없음. 기존 Chrome file URL 거부 및 localhost 우회 금지를 존중하여 같은 경로를 재시도하지 않음. 브라우저 경로에서는 이번에 새 접근을 시도하거나 거부당한 일이 없고 결과 불확실한 쓰기도 없음.
Microsoft Word/Hancom에서의 DOCX 열기와 브라우저 인쇄의 최종 페이지 나눔은 미검증.

남아 있는 제품 한계
기존 DOCX/PPTX/HWPX/PDF에서 사진을 추출해 업무·단계에 자동 연결하지 않음. 본문 초안을 활용하되 중요한 캡처는 사람이 설명 옆에 연결해야 함. PDF 표의 칸 관계를 자동 복원하지 않음.
HWP 직접 파싱·스캔 OCR·외부 AI 자동 해석은 지원하지 않음.
사진은 설명 구역(method/steps)에 연결되며 특정 단계 번호를 구조적으로 추적하지 않음. 캡션으로 어느 단계인지 적을 수 있음.
