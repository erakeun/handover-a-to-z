# 인수인계 A to Z

인계자는 아는 내용부터 적고, 인수자는 **업무 전체 / 언제 하는 일 / 지금 이어받을 건**에서 필요한 일을 찾는 브라우저 기반 인수인계 도구입니다. 문서·사진·PDF 근거를 서버에 올리지 않고 내 컴퓨터에서 다룹니다.

**웹앱:** https://erakeun.github.io/handover-a-to-z/

이 문서는 **0.3.3 변경과 병합 검토 내용**입니다. 이 문서가 존재하는 것만으로 운영 사이트의 배포 완료를 뜻하지 않습니다. 게시 후 운영 버전과 실제 동작을 별도로 확인해야 합니다.

## 사용하기

1. **인수인계서 만들기**에서 **업무명**과 **하는 방법**부터 적습니다. 모든 칸을 채울 필요는 없습니다. 받은 JSON은 **받은 인수인계서 보기**에서 엽니다.
2. **하는 방법**에 쓴 시작 안내는 인수 화면과 DOCX에서 그대로 읽습니다. 같은 내용을 ‘첫 행동’에 다시 쓸 필요는 없습니다. 필요하면 **첫 행동·근거 덧붙이기 (선택)**에 별도 안내와 PDF를 붙이고, 설명 옆에 사진을 추가합니다. 큰 업무 분류·일정·담당·자료·예외는 필요한 만큼 적습니다.
3. **업무 전체**에서는 큰 업무와 작은 업무 제목을 보고 설명으로 이동합니다. **언제 하는 일**에서는 확정된 일정과 날짜 미정 업무를 구분하고, **지금 이어받을 건**에서는 상태·다음 행동·연결된 업무를 봅니다. 검색 후 이 세 보기를 오가도 검색어를 유지합니다. 결과가 없으면 검색 조건을 확인하고 업무 전체 검색으로 돌아가거나 검색을 지울 수 있습니다.
4. 중요한 변경 후 **전달·백업 파일 받기 (.json)**를 누릅니다. 업무·사진·진행 건·현재 포함된 출처 발췌와 PDF가 단일 파일에 담깁니다. 실제 파일이 생겼는지 확인하고 별도로 보관하세요.
5. 제출하거나 문서 프로그램에서 읽을 때는 **업무 안내 전체 받기 (.docx)**를 사용합니다. 필요한 항목만 선택해 DOCX나 인쇄로 내보낼 수도 있습니다. 쪽 연결이 없는 PDF는 원문 전체를 한 번씩 뒤에 붙이거나 필요한 쪽만 직접 연결할 수 있습니다. 전체 부록 선택에는 파일별 쪽수와 추가 분량을 보여 주며, 업무와 관계없는 쪽이 포함될 수 있습니다. 같은 원문 부록 선택은 새로고침 전까지 재사용합니다. 직접 확인한 업무별 쪽 연결은 문서와 전달 JSON에 저장되어 다음 출력에서도 재사용됩니다. 한 쪽짜리 PDF는 별도 질문 없이 함께 넣습니다.

첫 화면의 **사진·PDF가 있는 가상 예시**로 촬영 접수와 사진, 월초·월말 반복, 조건표, 현재 진행 건, 미해석 원문·권한 예외의 다섯 유형을 살펴볼 수 있습니다. 실제 기관의 절차가 아닌 완전한 가상 자료입니다.

업무 설명 자체에 완료 체크를 붙이지 않습니다. 반복되는 방법과 실제 진행 건의 상태를 나눕니다. 상태를 확인하지 않은 기록은 **상태 미확인**으로 표시하고 이전 상태 값은 보존합니다. 직접 상태를 선택하면 현재 확인한 상태를 기록합니다. 이전 개인 수행 체크는 별도 보관할 수 있지만 새 개인 체크는 만들지 않습니다.

## 기존 문서와 근거 가져오기

**기존 문서로 시작**에서 PDF를 고르면 원문을 그대로 보존하고 업무명과 선택 사항인 짧은 안내로 시작합니다. 원문을 여러 카드로 다시 쓸 필요는 없습니다. 이미 담긴 PDF에서 **이 원문으로 다른 업무 안내**를 누르면 파일을 다시 고르지 않고 짧은 안내를 추가합니다. 기존 업무에도 담긴 PDF를 재사용할 수 있으며 원본 바이트를 중복 저장하지 않습니다. PDF 전체를 자동으로 여러 업무의 확정 절차로 만들지는 않습니다. 연결하기 전에 **PDF 전체 내용**을 전달해도 되는지 확인해야 합니다.

붙여넣은 메모는 **이대로 한 업무로 추가**로 빈 줄과 본문을 그대로 보존합니다. 여러 업무로 나누고 싶을 때만 초안 검토를 선택합니다. DOCX·PPTX·HWPX는 규칙으로 나눈 글 초안을 검토합니다. 제목과 업무 단위는 고칠 수 있고, 선택하지 않은 추출문도 출처 발췌에 남습니다. 원래 문서의 표·사진·배치·읽는 순서를 완전히 재현하지 않습니다. 담당이나 절차를 추측해 확정하지 않으므로 원문과 대조하세요.

| 형식 | 지원 범위 | 제한 |
| --- | --- | --- |
| JSON | v1·v2·v3·v4 검증, 미리보기, 새 사본 가져오기 | v1 5 MiB / v2·v3·v4 24 MiB. 새 문서와 편집한 문서는 v4이며 0.3.0 이하 앱에서 열 수 없습니다. |
| PDF 근거 | 원래 PDF를 JSON에 포함하고 업무에서 페이지 보기 | 한 파일 10 MiB·200쪽. 전체 PDF가 포함됩니다. OCR·암호화 PDF·표 구조 자동 복원은 지원하지 않습니다. |
| DOCX 가져오기 | 문단·표의 텍스트, 출처와 누락 경고 | 원래 서식·그림·도형을 완전히 재현하지 않습니다. |
| PPTX 가져오기 | 슬라이드 순서에 따른 글·표 텍스트 | 그림·차트·SmartArt·발표자 노트를 완전히 해석하지 않습니다. |
| HWPX 가져오기 | 구역의 본문·표 텍스트 | 한컴 문서의 모든 구조·서식 호환을 보장하지 않습니다. |
| HWP 가져오기 | 직접 읽지 않음 | HWPX/DOCX/PDF 변환 또는 텍스트 붙여넣기가 필요합니다. |
| DOCX·인쇄 | 업무지도, 실행 안내, 사진·캡션, 진행 건, 확인한 PDF 근거 쪽 또는 명시 선택한 원문 부록 | 근거 쪽은 이미지로 포함하며 한 번에 총 20쪽·32 MiB, 쪽당 8 MiB까지입니다. PDF 전체 바이트·전체 출처 발췌·내부 이력은 JSON에 남습니다. 외부에서 고친 DOCX는 앱에 자동 반영되지 않습니다. |

선택 출력에는 선택한 업무·진행 건과 연결된 PDF의 확인한 쪽 또는 명시 선택한 전체 원문을 넣습니다. 전체 원문은 업무마다 반복하지 않고 부록에 한 번만 들어갑니다. 이 선택을 업무별 확정 쪽 관계로 저장하지 않습니다. 원문 이미지 합계가 20쪽을 넘으면 전체 부록 선택은 제공하지 않습니다. 긴 PDF는 화면에서 보거나 JSON으로 그대로 전달할 수 있고, 출력할 때는 필요한 쪽을 직접 연결합니다. 범위 밖 업무를 가리킬 수 있는 공통 첫날·첫 주 안내는 선택 출력에서 제외하고, 전체 출력에서는 업무 안내 뒤에 둡니다. 필요한 근거 쪽이나 전체 원문 포함을 선택하지 않았거나 렌더에 실패하면 빠진 파일을 만드는 대신 출력을 중단합니다. DOCX의 근거 페이지는 원문 이미지이며 이미지 속 글은 문서 검색·표 셀 편집 대상이 아닙니다.

스캔 OCR은 없습니다. PDF·사진 속 글은 앱의 업무 검색 대상이 아니므로 연결된 원문을 열어 확인하세요. 일부 글이 추출되더라도 모든 내용이나 읽는 순서가 정확하다는 뜻은 아닙니다. 포함하지 않은 원본 전체까지 JSON이 보존하는 것은 아닙니다.

## 사진 넣기

- PNG·JPEG·정지 WebP를 파일 선택, 끌어놓기, 이미지 붙여넣기로 추가하는 기능을 제공합니다. 읽는 화면에서는 썸네일을 눌러 확대합니다.
- 입력 사진은 한 장 8 MiB, 한 변 8,192픽셀, 전체 1,600만 픽셀 이하입니다. SVG·HTML·움직이는 이미지는 지원하지 않습니다.
- 브라우저에서 전체 크기의 PNG로 다시 만들어 파일 메타데이터를 정리합니다. 저장 한도를 넘으면 작은 JPEG 선택안을 보여줍니다. 축소하면 글자가 흐려질 수 있고 투명 영역은 흰색이 되므로 확대해서 확인한 뒤 추가하세요. 원본 파일은 바뀌지 않습니다.
- 저장 사진은 한 장 2 MiB, 업무당 20장, 문서 전체 100장·16 MiB까지입니다. Base64로 담으므로 JSON은 사진 바이트 합계보다 커집니다. 사진이나 캡션에서 개인정보를 자동으로 가리지 않습니다.

## 저장·버전·복구

같은 브라우저의 자동 임시저장과 직접 받은 JSON 파일은 서로 다릅니다. **저장 중**과 **임시저장됨**을 구분하고, 실패·충돌 안내가 나오면 창을 닫기 전에 현재 내용을 JSON으로 보관하세요. 자동저장은 이미 내려받은 파일을 갱신하지 않습니다.

- 새 문서는 `schemaVersion: 4`입니다. 유효한 v1·v2·v3 파일을 읽거나 새 사본으로 가져오는 것만으로 버전을 올리지 않습니다. 내용을 편집하거나 근거 쪽 연결을 저장하면 v4가 됩니다. v4는 업무·진행 건별 근거 쪽 관계를 보존합니다. 각 버전에서 허용하지 않는 필드를 조용히 버리거나 변환하지 않습니다. 0.3.0 이하 앱은 v4 파일을 거부하며, 사람에게는 “이 파일은 최신 인수인계 A to Z에서 열어 주세요”라고 안내합니다.
- 새 저장은 기존 IndexedDB의 별도 `current-v4` 기록을 사용합니다. 0.3.0의 `current-v3`와 더 이전의 `current`, 이전 localStorage `.v3`·`.v1` 원문을 검증해 복사하고 바꾸거나 삭제하지 않습니다. IndexedDB 미지원 시에도 별도 v4 localStorage 키를 사용합니다.
- 이전 버전의 다른 창이 원본을 바꾸면 자동 덮어쓰기를 멈춥니다. 충돌한 원본과 현재 내용을 모두 보관한 뒤 확인해야 합니다.
- 앱을 0.3.0으로 되돌려도 새로 작성한 내용은 v4 저장에 남습니다. **0.3.0에는 v4에서 새로 쓴 내용이 표시되지 않으며 데이터가 구형 형식으로 내려가지 않습니다.** v4 JSON 백업을 보관하고 최신 앱에서 다시 열어야 합니다. 구버전용 변환을 위해 사진·PDF·진행 건·근거 쪽 연결을 삭제하지 않습니다.
- 임시저장은 문서 30개·직렬화된 UTF-8 합계 64 MiB까지이며 브라우저 실제 할당량은 더 작을 수 있습니다. 브라우저 데이터 삭제·기기 분실·시크릿 창 종료에 대비해 파일로 백업하세요. 다른 브라우저·포트·기기와 자동 동기화되지 않습니다.

구체적인 키와 형식은 [파일 형식과 보존 규칙](docs/data-format.md)에 설명합니다. 새 파일은 최신 앱을 사용하는 사람에게 전달하세요.

## 데이터와 개인정보

- 앱은 문서를 서버나 AI API에 보내지 않으며 분석 추적 도구를 넣지 않았습니다. AI는 선택 사항입니다. 사용자가 복사하거나 파일을 외부 AI에 전달하면 해당 서비스로 내용이 넘어갑니다.
- JSON·DOCX·AI용 텍스트는 암호화되지 않습니다. 비밀번호·인증키를 넣지 마세요. 사진과 PDF 전체의 공유 가능 여부를 확인하는 책임은 남습니다. 확인란은 개인정보 제거·권한·최신성 검사를 대신하지 않습니다.
- 공개 저장소에는 소스와 가상 예시·합성 테스트 자료만 둡니다.
- GitHub Pages는 정적 파일을 제공하며 방문 IP를 보안 목적으로 기록합니다. 앱의 문서 업로드와는 별개입니다. [GitHub Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)
- 같은 `erakeun.github.io` 아래 프로젝트는 브라우저의 동일 출처를 공유합니다. 앱 고유 저장 키를 쓰지만 별도 도메인 수준의 저장소 격리는 제공하지 않습니다.

## 개발 및 확인 범위

Node.js 22 이상에서:

```sh
npm ci --ignore-scripts
npm test
npm run check
npm run build
npm start
```

고정된 이전 모델과 비교하는 회귀 검사는 Git 객체 `da51d9039ff471ef174eaa476f905c078bd79cf8`이 필요합니다. 전체 이력이 있는 clone을 사용하거나 해당 커밋을 미리 fetch한 뒤 테스트하세요.

기본 로컬 주소는 `http://127.0.0.1:4173/`입니다. `HANDOVER_PORT=4186 npm start`처럼 포트를 지정할 수 있습니다. 빌드 결과는 `dist/`이며 PDF worker·가이드 이미지·라이선스 고지를 함께 배포합니다.

검증 이력은 [릴리스 검토 기록](REVIEW.md)을 참고하세요. 0.3.1 준비 중 실제 Chrome에서 본문만 작성한 업무의 시작 안내와 검색 후 일정·진행 건·업무 전체 왕복을 확인했습니다. 실제 UI로 내려받은 선택 DOCX 4쪽·전체 DOCX 12쪽과 Chrome에서 PDF로 저장한 3쪽을 렌더해 총 19쪽을 확인했습니다. 선택본에는 실행 단계와 PDF 조건표 이미지가 포함됩니다. 새로고침 후 전체 DOCX를 다시 받을 때 근거 쪽 질문 없이 저장 창에 진입하는 것도 확인했습니다. 최종 자동 검사 321개와 정적 검사·빌드·diff 검사를 통과했습니다. **다운로드 파일을 실제 파일 선택창으로 다시 여는 흐름은 자동화 확장의 file-URL 권한 거절로 미검증**이며 우회하지 않았습니다. 종이 인쇄·실제 초심자 수행 시험은 확인하지 않았습니다. 자동 검사에는 DOM·저장소 모형이 포함되므로 모든 브라우저의 보존이나 사람의 작업시간 감소를 입증하지 않습니다. 운영 게시 후 Pages 상태·버전·실제 화면을 별도로 확인해야 합니다.

## 배포

`main`에 소스와 검증된 `dist/`를 보관하고, GitHub Pages는 `gh-pages` 브랜치 루트의 정적 파일을 제공합니다. **PR을 `main`에 병합하는 것만으로 운영 배포되지는 않습니다.** 승인한 릴리스의 테스트·검사·빌드가 통과한 뒤 `main`의 `dist/`만 별도로 게시합니다.

```sh
git subtree split --prefix dist main
# 출력 커밋과 배포 대상을 확인한 뒤 gh-pages에 게시
```

게시 뒤 Pages 빌드 성공, 운영 버전, 실제 화면을 확인해야 배포 완료로 기록합니다. 다른 프로젝트의 파일이나 Pages 설정을 바꾸지 않습니다. 외부 패키지 고지는 [THIRD_PARTY_LICENSES.txt](THIRD_PARTY_LICENSES.txt)를 참고하세요.


### 0.3.2 사용 부담 개선

- 한 업무 DOCX는 짧은 실행 안내·예외·완료 기준을 먼저, 사진과 상세 근거는 뒤에 둡니다. 같은 합성 예시의 로컬 렌더는 선택 4→3쪽, 전체 12→10쪽이며 글씨·이미지를 축소한 결과가 아닙니다.
- 여러 항목이 같은 PDF 쪽을 쓰면 항목을 직접 선택해 쪽 번호를 한 번만 입력합니다. 관계를 자동으로 추측하지 않고 확인된 연결은 재사용합니다. 항목별 다른 입력도 가능합니다.
- ‘언제 하는 일’에서 오늘 확인된 일정과 회신 대기를 함께 봅니다. 기한·상태 미확인 기록은 별도로 남으며 날짜를 만들어 넣지 않습니다.
- 완료한 진행 건의 다음 행동과 기다리던 회신은 완료 전 기록으로 표시합니다. 다시 진행 상태로 바꾸면 원래 안내가 돌아옵니다.

JSON 형식과 저장 키는 0.3.1의 v4를 유지합니다. 0.3.1과 파일 호환되며, 원본·사진·PDF·기존 임시저장을 지우는 마이그레이션은 없습니다. 파일 선택 권한 제한으로 실제 JSON 재열기는 미검증이며, 코어 왕복 검사는 실제 브라우저 파일 열기와 구분합니다.


### 0.3.3 원문을 살리는 짧은 안내

- 자연어 메모를 강제로 나누지 않고 한 업무로 바로 추가합니다. 별도 첫 행동·분류·날짜는 필수가 아닙니다.
- 같은 PDF를 다시 첨부하거나 원문을 복사하지 않고 업무별 짧은 안내를 추가합니다. 쪽 관계를 자동 추측하지 않습니다.
- 작은 원문은 업무별 쪽 판단 대신 전체를 부록에 한 번 넣을 수 있습니다. 원문 쪽수·선택 범위·미확정 관계를 표시하며 20쪽 한도를 유지합니다.
- 같은 예시에서 전체 부록 선택은 8개 쪽 관계 확인 대신 1회 범위 선택, 쪽 번호 입력 0회입니다. 다만 선택 DOCX는 3→4쪽입니다. 늘어난 한 쪽은 원문 전체를 전달하기 위한 것이며 그 업무의 필수 근거라고 확정하지 않았습니다. 필요한 1쪽만 이미 연결한 출력은 기존 3쪽을 유지합니다.

JSON v4와 저장 키는 유지합니다. 원문 부록 선택은 출력용 세션 선택이며 파일 형식을 바꾸지 않습니다. 이번 범위는 main 병합까지로, gh-pages 게시 및 운영 버전 변경은 별도 승인 대상입니다.
