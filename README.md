# 인수인계 A to Z

인계자는 빠르게 작성하고 인수자는 필요한 업무부터 찾아보는 브라우저 기반 인수인계 도구입니다.

**웹앱:** https://erakeun.github.io/handover-a-to-z/

이 문서는 **소스 검토본 0.2.0**을 설명합니다. 사진 첨부·새 임시저장·업무 개요 변경은 아직 운영 배포하지 않았으며, 공개 웹앱은 0.1.1입니다. 이전 앱에서는 사진이 포함된 v2 JSON을 열 수 없습니다.

큰 업무와 세부 업무를 나누어 작성하고, 인수자는 첫날·첫 주 안내, 달력, 진행 건과 확인 필요 항목으로 살펴봅니다. 가상 예시는 큰 업무 3개, 세부 업무 10개, 진행 건 3개입니다.

## 사용하기

1. **인수인계서 만들기** 또는 **받은 인수인계서 보기**로 시작합니다. 기존 문서와 가상 예시도 선택할 수 있습니다.
2. 업무명과 하는 방법부터 적습니다. 설명·단계 옆의 **사진 넣기**로 화면 캡처를 붙이고 짧은 설명을 적을 수 있습니다. 큰 업무 분류·일정·자료·예외는 필요할 때 추가합니다.
3. 인수자 보기에서 전체 업무·이번 주·진행 중인 일을 확인합니다. **내 업무 한눈에 보기**는 입력된 담당·큰 업무·업무명을 자동으로 모읍니다. 업무명을 누르면 상세로 이동하며 다시 개요로 돌아올 수 있습니다. 담당을 적지 않은 업무는 **담당 미입력**으로 표시합니다.
4. 중요한 변경 후 **파일로 저장**을 눌러 사진과 설명이 함께 담긴 **단일 `.json` 파일**을 보관합니다. 별도 이미지 폴더나 ZIP은 필요하지 않습니다. 다른 기기에서는 **받은 파일 열기**로 해당 파일을 엽니다.
5. 제출에는 **전체 문서 받기 (.docx)**를 사용합니다. 일부만 출력하려면 **출력할 업무 선택 · 인쇄**를 펼칩니다.

문서나 메모에서 여러 업무를 가져올 때 요약을 보고 필요한 내용만 펼칩니다. 제목 후보에서는 선행 쪽번호·명확한 작성 기준일을 건너뛰고, 반복되는 페이지·슬라이드 제목에 다음 짧은 줄을 붙여 구분합니다. 이는 편집 가능한 규칙 기반 제안이며 원문을 바꾸거나 담당·업무 분류를 추측하지 않습니다. 검색한 초안을 함께 선택·해제하고 기존 큰 업무 영역에 함께 분류할 수 있습니다. 검색 밖의 선택은 유지되며 선택하지 않은 추출 내용도 출처 원문에 보존합니다.

출력할 업무·진행 건을 고르면 화면을 오가는 동안 선택이 유지됩니다. 같은 선택으로 DOCX·인쇄·AI용 텍스트를 만들 수 있으며, 나중에 추가한 항목은 직접 선택합니다. DOCX와 인쇄에는 선택한 업무의 사진·캡션을 포함하며 끝에 업무 개요를 붙입니다. AI용 텍스트에는 사진 바이트를 넣지 않습니다. 브라우저 새로고침 후에는 출력할 항목을 다시 선택하세요.

## 사진 넣기

- PNG·JPEG·정지 WebP를 파일 선택, 설명 영역으로 끌어놓기, 이미지 붙여넣기로 추가합니다. 읽는 화면에서는 썸네일을 눌러 확대합니다. 삭제 전에는 확인합니다.
- 원본 한 장은 8 MiB 이하, 한 변 8,192픽셀 이하, 전체 1,600만 픽셀 이하입니다. SVG·HTML·움직이는 이미지는 지원하지 않습니다.
- 브라우저에서 읽은 사진을 전체 크기의 PNG로 다시 만들어 파일 메타데이터를 정리합니다. 저장 한도에 맞지 않으면 작은 JPEG 선택안을 보여줍니다. 압축·축소하면 글자가 흐려질 수 있고 투명한 부분은 흰색이 되므로 확대해서 확인한 뒤 추가하세요. 원본 파일은 바뀌지 않습니다.
- 저장할 사진은 한 장 2 MiB, 한 업무 20장, 문서 전체 100장·16 MiB까지입니다. JSON에 사진 바이트를 문자로 담으므로 파일은 이미지 용량 합계보다 커집니다. 사진 포함 v2 JSON 전체 한도는 24 MiB입니다.
- 사진이나 캡션에서 개인정보를 자동으로 가리지 않습니다. 공유 전 본문과 사진을 함께 확인하세요.

## 데이터와 개인정보

- 입력·가져온 문서의 처리는 브라우저 안에서 이루어집니다. 앱은 문서를 서버나 AI API에 보내지 않으며 분석 추적 도구도 넣지 않았습니다.
- 편집 중 내용은 화면의 메모리에 있으며, 문서·사진의 자동 임시저장은 이 브라우저의 IndexedDB에 보관합니다. **저장 중**과 **자동 저장됨**을 구분하고 저장 트랜잭션이 완료된 뒤에만 성공으로 표시합니다.
- 임시저장 한도는 문서 30개·합계 UTF-8 64 MiB입니다. 실제 사용 가능한 용량은 브라우저 환경에 따라 더 작을 수 있습니다. 실패·충돌 안내가 나오면 창을 닫기 전에 현재 내용을 JSON으로 직접 백업하세요. 임시저장 성공은 파일 백업을 뜻하지 않습니다.
- 이전 localStorage 문서는 검증 후 새 저장소로 옮기며 이전 저장 원문을 삭제하지 않습니다. IndexedDB 미지원 환경은 안내 후 기존 저장소를 사용하지만, 열기 실패·차단을 미지원으로 간주해 조용히 덮어쓰지 않습니다.
- 업무 수행 기록은 원본 문서와 별도 저장합니다. 저장소 삭제·시크릿 창 종료·기기 교체에 대비해 문서는 JSON으로, 수행 기록은 별도 파일로 보관하세요.
- JSON·DOCX·AI용 텍스트는 암호화되지 않습니다. 비밀번호·인증키를 입력하지 마세요.
- 선택 AI 기능은 사용자가 미리보기를 확인한 뒤 직접 복사하는 방식입니다. 외부 AI에 붙여넣으면 해당 서비스로 내용이 전달됩니다.
- 공개 저장소에는 소스와 가상 예시·합성 테스트 문서만 있습니다.
- GitHub Pages는 정적 파일을 제공하며 방문 IP를 보안 목적으로 기록합니다. 이는 앱의 문서 업로드나 분석 추적과는 별개입니다. [GitHub Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)
- 같은 `erakeun.github.io` 아래 프로젝트들은 브라우저의 동일 출처를 공유합니다. 이 앱은 고유한 저장 키를 사용하지만 별도 도메인 수준의 저장소 격리는 제공하지 않습니다.

## 문서 지원 범위

| 기능 | 지원 범위 | 제한 |
|---|---|---|
| JSON | v1 호환, 사진을 포함하는 v2, 검증·미리보기·새 사본 가져오기 | v1 5 MiB / v2 24 MiB. 암호화 파일 아님. 이전 앱은 v2 미지원 |
| DOCX 가져오기 | 문단과 표의 텍스트, 출처와 누락 경고 | 원래 서식·그림·도형을 완전히 재현하지 않음 |
| PPTX 가져오기 | 슬라이드 순서에 따른 글·표 텍스트 | 그림·차트·SmartArt·발표자 노트 완전 해석 안 됨 |
| HWPX 가져오기 | 구역의 본문·표 텍스트 | 한컴 문서의 모든 구조·서식 호환 보장 안 됨 |
| PDF 가져오기 | 텍스트 레이어를 페이지별 추출, 쪽번호만 읽힌 페이지의 확인 경고 | 사진·화면 캡처·이미지 속 글자 미포함. 표 구조 복원·OCR·암호화 PDF 미지원 |
| HWP 가져오기 | 직접 읽지 않음 | HWPX/DOCX/PDF 변환 또는 텍스트 붙여넣기 안내 |
| DOCX 내보내기 | 전체·선택 업무/진행 건, 사진·캡션, 끝부분 업무 개요를 포함한 실제 DOCX 생성 | 선택 출력에도 문서 공통 첫날·첫 주 안내가 포함됨. 외부 수정 내용이 JSON에 자동 동기화되지 않음 |

추출 결과는 사용자가 업무별로 나누고 합치는 규칙 기반 초안입니다. 기존 문서 속 사진·화면 캡처가 자동으로 붙거나 업무·단계에 연결되지는 않습니다. 추출된 본문을 활용하면서 필요한 사진을 설명 옆에 추가하고, 표·읽기 순서·누락 경고를 원문과 대조하세요. 원본 파일은 덮어쓰지 않습니다.

## 개발 및 로컬 실행

Node.js 22 이상에서:

```sh
npm ci --ignore-scripts
npm test
npm run check
npm run build
npm start
```

로컬 서버는 `127.0.0.1:4173`에만 바인딩합니다. 빌드 결과는 `dist/`입니다. PDF worker와 라이선스 고지를 포함한 모든 실행 자원을 함께 배포합니다.

검증은 데이터·날짜·문서 처리·저장·DOM 통합 테스트와 정적 검사를 포함합니다. 새 사진 기능과 IndexedDB의 자동 검증은 합성 자료, DOM 에뮬레이션과 저장소 모형을 사용합니다. **실제 브라우저의 파일 선택·이미지 클립보드·다운로드·인쇄·새로고침·탭 종료 동작은 이번 변경에서 미검증입니다.** 모형 테스트는 실제 코덱·브라우저·보조기술 검증을 대신하지 않습니다. 이전 PC 사용 흐름의 관찰 범위는 [PC 사용성 검토 기록](docs/PC-USABILITY-REVIEW.txt)을 참고하세요.

## 배포

`main`에는 소스와 검증된 `dist/`를 보관합니다. GitHub Pages는 `gh-pages` 브랜치 루트의 정적 파일을 제공합니다. 소스 병합만으로 운영 배포하지 않습니다. 새 배포는 별도 승인 후 테스트·검사·빌드를 통과한 `main`의 `dist/`만 게시합니다.

```sh
git subtree split --prefix dist main
# 출력된 커밋을 확인한 후 gh-pages 브랜치로 push
```

새 유료 서비스·도메인·인증키가 필요하지 않습니다. 다른 프로젝트의 파일과 Pages 설정은 변경하지 않습니다. 데이터 구조는 [docs/data-format.md](docs/data-format.md), 외부 패키지 고지는 [THIRD_PARTY_LICENSES.txt](THIRD_PARTY_LICENSES.txt)를 참고하세요.
