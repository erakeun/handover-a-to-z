# 인수인계 A to Z

인계자는 아는 내용부터 적고, 인수자는 **업무 전체 / 언제 하는 일 / 지금 이어받을 건**에서 필요한 일을 찾는 브라우저 기반 인수인계 도구입니다. 문서·사진·PDF 근거를 서버에 올리지 않고 내 컴퓨터에서 다룹니다.

**웹앱:** https://erakeun.github.io/handover-a-to-z/

이 문서는 **0.3.0 변경과 릴리스 준비 내용**입니다. 이 문서가 존재하는 것만으로 운영 사이트의 배포 완료를 뜻하지 않습니다. 게시 후 운영 버전과 실제 동작을 별도로 확인해야 합니다.

## 사용하기

1. **인수인계서 만들기**에서 **업무명**과 **하는 방법**부터 적습니다. 모든 칸을 채울 필요는 없습니다. 받은 JSON은 **받은 인수인계서 보기**에서 엽니다.
2. 필요하면 **첫 행동·근거 덧붙이기 (선택)**에 시작 행동 한 줄과 PDF를 붙입니다. 설명 옆에 사진을 추가할 수도 있습니다. 큰 업무 분류·일정·담당·자료·예외는 필요한 만큼 적습니다.
3. **업무 전체**에서는 큰 업무와 작은 업무 제목을 보고 설명으로 이동합니다. **언제 하는 일**에서는 날짜가 확정된 일정과 월초·월말 등 날짜 미정 업무를 구분합니다. **지금 이어받을 건**에서는 실제 진행 건의 상태·다음 행동·연결된 업무를 봅니다.
4. 중요한 변경 후 **전달·백업 파일 받기 (.json)**를 누릅니다. 업무·사진·진행 건·현재 포함된 출처 발췌와 PDF가 단일 파일에 담깁니다. 실제 파일이 생겼는지 확인하고 별도로 보관하세요.
5. 제출하거나 문서 프로그램에서 읽을 때는 **업무 안내 전체 받기 (.docx)**를 사용합니다. 필요한 항목만 선택해 DOCX나 인쇄로 내보낼 수도 있습니다.

첫 화면의 **사진·PDF가 있는 가상 예시**로 촬영 접수와 사진, 월초·월말 반복, 조건표, 현재 진행 건, 미해석 원문·권한 예외의 다섯 유형을 살펴볼 수 있습니다. 실제 기관의 절차가 아닌 완전한 가상 자료입니다.

업무 설명 자체에 완료 체크를 붙이지 않습니다. 반복되는 방법과 실제 진행 건의 상태를 나눕니다. 상태를 확인하지 않은 기록은 **상태 미확인**으로 표시하고 이전 상태 값은 보존합니다. 직접 상태를 선택하면 현재 확인한 상태를 기록합니다. 이전 개인 수행 체크는 별도 보관할 수 있지만 새 개인 체크는 만들지 않습니다.

## 기존 문서와 근거 가져오기

**기존 문서로 시작**에서 PDF를 고르면 먼저 업무 하나의 근거로 연결합니다. 제목과 아는 내용부터 적고 원래 페이지를 보며 필요한 안내를 덧붙입니다. PDF 전체를 자동으로 여러 업무의 확정 절차로 만들지는 않습니다. 연결하기 전에 **PDF 전체 내용**을 전달해도 되는지 확인해야 합니다.

DOCX·PPTX·HWPX와 붙여넣은 메모는 규칙으로 나눈 글 초안을 검토합니다. 제목과 업무 단위는 고칠 수 있고, 선택하지 않은 추출문도 출처 발췌에 남습니다. 원래 문서의 표·사진·배치·읽는 순서를 완전히 재현하지 않습니다. 담당이나 절차를 추측해 확정하지 않으므로 원문과 대조하세요.

| 형식 | 지원 범위 | 제한 |
| --- | --- | --- |
| JSON | v1·v2·v3 검증, 미리보기, 새 사본 가져오기 | v1 5 MiB / v2·v3 24 MiB. 새 문서와 편집한 문서는 v3이며 0.2.0 이하 앱에서 열 수 없습니다. |
| PDF 근거 | 원래 PDF를 JSON에 포함하고 업무에서 페이지 보기 | 한 파일 10 MiB·200쪽. 전체 PDF가 포함됩니다. OCR·암호화 PDF·표 구조 자동 복원은 지원하지 않습니다. |
| DOCX 가져오기 | 문단·표의 텍스트, 출처와 누락 경고 | 원래 서식·그림·도형을 완전히 재현하지 않습니다. |
| PPTX 가져오기 | 슬라이드 순서에 따른 글·표 텍스트 | 그림·차트·SmartArt·발표자 노트를 완전히 해석하지 않습니다. |
| HWPX 가져오기 | 구역의 본문·표 텍스트 | 한컴 문서의 모든 구조·서식 호환을 보장하지 않습니다. |
| HWP 가져오기 | 직접 읽지 않음 | HWPX/DOCX/PDF 변환 또는 텍스트 붙여넣기가 필요합니다. |
| DOCX·인쇄 | 업무지도, 실행 안내, 사진·캡션, 진행 건 | PDF 자체·전체 출처 발췌·내부 이력은 JSON에 남습니다. 외부에서 고친 DOCX는 앱에 자동 반영되지 않습니다. |

스캔 OCR은 없습니다. PDF·사진 속 글은 앱의 업무 검색 대상이 아니므로 연결된 원문을 열어 확인하세요. 일부 글이 추출되더라도 모든 내용이나 읽는 순서가 정확하다는 뜻은 아닙니다. 포함하지 않은 원본 전체까지 JSON이 보존하는 것은 아닙니다.

## 사진 넣기

- PNG·JPEG·정지 WebP를 파일 선택, 끌어놓기, 이미지 붙여넣기로 추가하는 기능을 제공합니다. 읽는 화면에서는 썸네일을 눌러 확대합니다.
- 입력 사진은 한 장 8 MiB, 한 변 8,192픽셀, 전체 1,600만 픽셀 이하입니다. SVG·HTML·움직이는 이미지는 지원하지 않습니다.
- 브라우저에서 전체 크기의 PNG로 다시 만들어 파일 메타데이터를 정리합니다. 저장 한도를 넘으면 작은 JPEG 선택안을 보여줍니다. 축소하면 글자가 흐려질 수 있고 투명 영역은 흰색이 되므로 확대해서 확인한 뒤 추가하세요. 원본 파일은 바뀌지 않습니다.
- 저장 사진은 한 장 2 MiB, 업무당 20장, 문서 전체 100장·16 MiB까지입니다. Base64로 담으므로 JSON은 사진 바이트 합계보다 커집니다. 사진이나 캡션에서 개인정보를 자동으로 가리지 않습니다.

## 저장·버전·복구

같은 브라우저의 자동 임시저장과 직접 받은 JSON 파일은 서로 다릅니다. **저장 중**과 **임시저장됨**을 구분하고, 실패·충돌 안내가 나오면 창을 닫기 전에 현재 내용을 JSON으로 보관하세요. 자동저장은 이미 내려받은 파일을 갱신하지 않습니다.

- 새 문서는 `schemaVersion: 3`입니다. 유효한 v1·v2 파일을 읽거나 새 사본으로 가져오는 것만으로 버전을 올리지 않습니다. 내용을 편집하면 v3로 저장합니다. 각 버전에서 허용하지 않는 필드를 조용히 버리거나 변환하지 않습니다.
- 새 저장은 기존 IndexedDB의 별도 `current-v3` 기록을 사용합니다. 이전 `current`와 이전 localStorage `.v1` 원문을 검증해 복사하고 원본은 바꾸거나 삭제하지 않습니다. IndexedDB 미지원 시에도 별도 v3 localStorage 키를 사용합니다.
- 이전 버전의 다른 창이 원본을 바꾸면 자동 덮어쓰기를 멈춥니다. 충돌한 원본과 현재 내용을 모두 보관한 뒤 확인해야 합니다.
- 앱을 구버전으로 되돌려도 새로 작성한 내용은 v3 저장에 남습니다. **구버전 앱에는 그 내용이 표시되지 않으며 데이터가 구형 형식으로 내려가지 않습니다.** v3 JSON 백업을 보관하고 최신 앱에서 다시 열어야 합니다.
- 임시저장은 문서 30개·직렬화된 UTF-8 합계 64 MiB까지이며 브라우저 실제 할당량은 더 작을 수 있습니다. 브라우저 데이터 삭제·기기 분실·시크릿 창 종료에 대비해 파일로 백업하세요. 다른 브라우저·포트·기기와 자동 동기화되지 않습니다.

구체적인 키와 형식은 [파일 형식과 보존 규칙](docs/data-format.md)에 설명합니다. 새 파일은 최신 앱을 사용하는 사람에게 전달하세요.

## 데이터와 개인정보

- 앱은 문서를 서버나 AI API에 보내지 않으며 분석 추적 도구를 넣지 않았습니다. AI는 선택 사항입니다. 사용자가 복사하거나 파일을 외부 AI에 전달하면 해당 서비스로 내용이 넘어갑니다.
- JSON·DOCX·AI용 텍스트는 암호화되지 않습니다. 비밀번호·인증키를 넣지 마세요. 사진과 PDF 전체의 공유 가능 여부를 확인하는 책임은 남습니다. 확인란은 개인정보 제거·권한·최신성 검사를 대신하지 않습니다.
- 공개 저장소에는 소스와 가상 예시·합성 테스트 자료만 둡니다.
- GitHub Pages는 정적 파일을 제공하며 방문 IP를 보안 목적으로 기록합니다. 앱의 문서 업로드와는 별개입니다. [GitHub Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)
- 같은 `erakeun.github.io` 아래 프로젝트는 브라우저의 동일 출처를 공유합니다. 앱 고유 저장 키를 쓰지만 별도 도메인 수준의 저장소 격리는 제공하지 않습니다.

## 개발 및 확인 범위

Node.js 22 이상에서:

```sh
npm ci --ignore-scripts
npm test
npm run check
npm run build
npm start
```

고정된 이전 모델과 비교하는 회귀 검사는 Git 객체 `da51d9039ff471ef174eaa476f905c078bd79cf8`이 필요합니다. 전체 이력이 있는 clone을 사용하거나 해당 커밋을 미리 fetch한 뒤 테스트하세요.

기본 로컬 주소는 `http://127.0.0.1:4173/`입니다. `HANDOVER_PORT=4186 npm start`처럼 포트를 지정할 수 있습니다. 빌드 결과는 `dist/`이며 PDF worker·가이드 이미지·라이선스 고지를 함께 배포합니다.

검증 이력은 [0.3.0 릴리스 검토 기록](REVIEW.md)을 참고하세요. 릴리스 준비 단계의 자동 검사·정적 검사·빌드를 통과했고, 가상 PDF 렌더·실제 브라우저 다운로드·로컬 Chrome의 새 v3 저장 후 새로고침 복원을 확인했습니다. **다운로드 파일을 실제 파일 선택창으로 다시 여는 흐름은 자동화 확장의 file-URL 권한 거절로 미검증**이며 우회하지 않았습니다. 실제 인쇄창·초심자 수행 시험도 확인하지 못했습니다. 자동 검사에는 DOM·저장소 모형이 포함되므로 모든 브라우저에서의 보존이나 작업시간 감소를 입증하지 않습니다. 운영 사이트 게시 후 동작은 별도로 확인해야 합니다.

## 배포

`main`에 소스와 검증된 `dist/`를 보관하고, GitHub Pages는 `gh-pages` 브랜치 루트의 정적 파일을 제공합니다. **PR을 `main`에 병합하는 것만으로 운영 배포되지는 않습니다.** 승인한 릴리스의 테스트·검사·빌드가 통과한 뒤 `main`의 `dist/`만 별도로 게시합니다.

```sh
git subtree split --prefix dist main
# 출력 커밋과 배포 대상을 확인한 뒤 gh-pages에 게시
```

게시 뒤 Pages 빌드 성공, 운영 버전, 실제 화면을 확인해야 배포 완료로 기록합니다. 다른 프로젝트의 파일이나 Pages 설정을 바꾸지 않습니다. 외부 패키지 고지는 [THIRD_PARTY_LICENSES.txt](THIRD_PARTY_LICENSES.txt)를 참고하세요.
